version: "0.22.0"
date: 2026-09-18
headline: "Raid Composition goes public — role taxonomy, encounter checker, and pack import/export — alongside the Planes of Power flag tracker and Faction Tracker, plus one level of trigger category nesting."
highlights:
  - "**Raid Composition is public** — a new **Raids** section: a user-editable role taxonomy, a normalized encounter knowledge base, and a live MIN/REC composition checker run against the current Zeal raid roster (or a manually-entered one), plus a Raid Summary dashboard tab showing encounter-agnostic per-class coverage and a Raid Readiness overlay (dashboard panel + popout window) surfacing missing MIN-role classes at a glance. Contributed by Kav (Intervention), ported from his eqmon project. Encounters can now be exported and imported as packs, auto-provisioning any taxonomy roles a pack references that don't exist locally yet. The composition check's encounter is always a manual pick, kept in sync across the check page, dashboard panel, and popout overlay, and the picker orders by proximity to your live zone. Follow-up fixes from a real raid in Kael Drakkel: Zeal's raid roster wire format sends class as a name and level as a string rather than the numbers first assumed, which had silently dropped every roster update — the decoder now tolerates both. Candidate names on a short row are class-eligible members, not actual assignments, so the same person can be counted toward more than one role's need at once; treat the report as a staffing guide, not a final call. No longer gated behind Developer settings — it's a permanent nav item now."
  - "**PoP Flags and Faction Tracker are public too** — with Planes of Power approaching on Project Quarm, the per-character PoP planar-progression checklist and the session Faction Tracker (faction wishlist + best-effort standing tally from your log) no longer need a Developer-tab flag either. The only two toggles left in Settings → Developer → Flags are the Planes of Power era preview and the experimental raid-wide threat meter."
  - "**Trigger categories can nest one level deep** — a category can now hold subcategories, shown indented under their parent wherever categories appear (the trigger list, the pack filter, bulk edit). A GINA import's flattened \"Parent/Child\" category names, or any existing slash-named category, can be split into a real parent/child pair with one click via a new scissors icon. Reparenting a childless custom category between the top level and any other top-level category is done through an explicit Parent picker rather than drag-and-drop (which still handles reordering and moving triggers between categories exactly as before)."
  - "**Same-named slow targets get their own timer again** — slowing two identically-named mobs at once used to show only one countdown on the detrimental overlay, since the log line that starts a custom timer carries no spawn id to tell them apart. With a current Zeal build, your own self-cast slows now disambiguate by the target's live spawn id, so each mob gets its own timer. This only covers your own client casting its own slows — a slow cast by someone else in the raid, or by an NPC, still can't be told apart by name alone."
  - "**Old .bak.txt archives can be compressed retroactively** — Archive & Trim has zipped new rotated-out logs to .bak.zip for a while now; a new \"Old backup logs\" card in Settings → Backfill compresses any legacy .bak.txt files left over from before that change, in place, per character."
  - "**Buff and detrimental timers can show seconds** — a new setting keeps the countdown in minutes:seconds past the 60-second mark instead of switching to whole minutes."
fixes:
  - "**Custom timers linked to a spell no longer run long** — a \"New Trigger from Spell\" custom timer (e.g. a Paragon or Savagery recast timer built to inherit the spell's icon) was having your own AA/item buff-duration extensions applied on top of the trigger editor's configured duration, making the on-screen timer outlast what you set. Duration extension now only applies to real buff timers."
  - "**NPC overlay and target tracking no longer break with Zeal's spawn-id label option on** — Zeal 1.4.7 added a \"/labels showtargetspawnid\" toggle that renders target names like \"Kaas Thox Xi Aten Ha Ra (1234)\". Anyone with it enabled got a blank NPC overlay and broken target attribution across combat and the threat trackers, since all of them keyed off the exact label text. The spawn-id suffix is now stripped before anything reads the name."
